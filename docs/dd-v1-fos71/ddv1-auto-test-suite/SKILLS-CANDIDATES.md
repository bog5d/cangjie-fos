## 1. 候选 ①（**升级**）：`devops/real-env-gate-ops`

**触发条件**：任何「云端/CI 绿了，要在真机或新环境复跑验收」的关卡任务；任何**交付门禁**类任务。

**旧错误（本轮实证）**：
- 验收跑的是**与生产入口平行的另一条链路**（本轮：端到端测试跑 `dd_v1_local_run.py`，真实跑的是 `dd_team_channel.py run --package`）；
  ⇒ 两套链路的**连接键从未相遇** ⇒ 真实事故（义务 ID 对不上、0 件交付）**结构上不可见**。
- 断言**找不到输入也报 PASS**（本轮：披露闸断言找不到交付清单却返回 PASS）⇒ **假绿**。
- 阈值**事后随结果讨论** ⇒ 门禁失去意义。

**根因**：验收证据的**链路**与**标识空间**没有与被测对象对齐；断言没有 fail-closed 纪律。

**正确步骤（可执行）**：
1. **同一条入口**：端到端证据必须由**生产入口**产出（CLI/服务），测试不得另造平行入口。
2. **标识同源**：测试/标准答案里的业务标识**从被测系统的权威契约导出**；禁止自造 ID 空间。
3. **夹具先验非退化**：造数后先断言「题目落在互不相同的组合上」；否则满分是假象。
4. **断言 fail-closed**：找不到输入 ⇒ FAIL；并把「跳过/排除的项」**写进报告**。
5. **阈值考试前冻结**：进版本控制、附 `frozen_at`；改阈值＝换版本 ＋ 留差异说明。
6. **环境口径写进报告**：代理变量、缺依赖等**如实记账**，不隐藏失败条目。

**适用边界**：不适用于「纯业务判断」验收（Gold 对不对、披露授权）——那些**必须留给人**。

**验证案例（本轮）**：
- 反例：PR#86 端到端「7 passed / 0 failed」＋ Windows 真实考试「分数出不来」⇒ 同一条链路的两个世界。
- 正例：本轮考试台三场考试（A/B/C）走**生产入口**，Gold 由**库侧契约导出** ⇒ D1（分簇 ID 与 Gold 对不上）在第一场考试就被抓出并修复。

## 2. 候选 ②（**升级**）：`software-development/python-test-fixture-portability`

**触发条件**：写/审测试夹具、造合成数据、给端到端测试准备标准答案时。

**旧错误（本轮实证）**：
- 夹具里的标准答案用 `R1-O1` 这种**生产系统里不存在的号** ⇒ 标准答案与被测系统**没有共享标识空间**
  ⇒ 任何「ID 对不上」类缺陷**结构性不可见**。
- 42 题卷因「主体与类型同余」只落在 **3 份材料**上 ⇒ 召回率满分是**假象**（规模根本没被测到）。

**根因**：夹具的**标识**与**分布**都没有与真实业务对齐，却用同一套断言评它。

**正确步骤**：
1. **标识同源**：夹具里的义务/实体标识**从被测系统的权威接口导出**；若标识不稳定（uuid 主键），
   用**内容派生的稳定键**（如 `obligation_key`）并在阅卷侧做**绑定 ＋ 如实记账**（绑不上的条目必须报出来）。
2. **非退化自检**：造数脚本跑完先自检（题目数、**不同材料数**、组合是否互不相同），
   断言不过 ⇒ **先修夹具**再跑考试。
3. **期望按业务语义表达**（题号 ＋ 材料相对路径），**不手写**系统内部标识。
4. **夹具自包含**：不依赖外部机器状态；跨平台路径/编码要显式处理。

**适用边界**：不适用于「故意构造非法输入」的负例夹具（那类要**故意**破坏标识空间）。

**验证案例（本轮）**：
- 反例：`backend/tests/fixtures/dd-v1-fos71-a5/gold.json`（`obligation_id: "R1-O1"`）⇒ 与生产系统无交集。
- 正例：`backend/tests/fixtures/dd-v1-exam-suite/`（期望按题号＋相对路径；Gold 由 `build_gold()` 从契约导出）
  ＋ `test_dd_v1_exam_suite_l1.py::test_fixture_c_is_not_degenerate`（非退化自检）。

## 3. 候选 ③（**新建**）：`devops/ai-auto-exam-gate`

> 查重结论：现有 Skills 里**没有**覆盖「**AI 自主考试台（三层）＋ 自动标准答案评分 ＋ 冻结阈值交付门禁**」的；
> `real-env-gate-ops` 管的是**环境**关卡，`test-driven-development` 管的是**写法**，都装不下这套东西 ⇒ **新建**。

**触发条件**：AI 写的系统要「**自己证明自己能用**」时；交付前要设**机器门禁**时；
任何「开发者宣布完成 → 人工发现基础 Bug」反复发生的项目。

**旧错误（本轮实证）**：
- 「工程测试全绿」与「真实业务链路通不通」之间**没有连接**；真实事故要等**人工真机**才暴露。
- 「模型参与了」只测到**适配器存在**，没测到**进程真的跑、请求真的发出、响应真的收到**。
- 人工承担了**本该机器做**的基础测试（真实事故里全是基础 Bug）。

**根因**：缺少「**考试台**」这一层——把「被测系统」当成「考生」，把「标准答案」当成「阅卷器」，
把「交付」当成「有门禁」。

**正确步骤**：
1. **建考场**：隔离数据面（仓库之外）＋ 合成材料库 ＋ 固定清单 ＋ 合成标准答案 ＋ 证据目录。
2. **三层考试**：
   - **L1 程序层**：不依赖模型的规则/契约/回归（每次提交自动跑）；
   - **L2 模拟模型**：用可控的模拟模型跑完整链路（**只能证明流程**，不能证明真实模型）；
   - **L3 真实模型**：**进程级**参与证明（进程启动 ＋ 请求指纹 ＋ 响应落盘 ＋ 盖章来源）。
3. **自动评分**：逐题明细 ＋ 分层指标 ＋ 0—100 总分；**保留原始分母**；`NOT_SCORABLE` 只用于客观不可评分。
4. **交付门禁**：G1 基础 / G2 模拟端到端 / G3 真实模型 / G4 Gold 评分阈值 / G5 安全 / G6 独立复核 / G7 交接包；
   阈值**考试前冻结**；任一关键门槛红 ⇒ **不得宣布完成、不得发人工验收请求**。
5. **失败驱动修复**：失败 ⇒ 留证据 ⇒ 定根因 ⇒ **加能复现的测试** ⇒ 改代码 ⇒ 回归 ⇒ 留证据。
6. **人工只做机器做不了的**：业务准确性、Gold 业务判断、披露授权、目标平台真机。

**适用边界**：
- **不适用于**「没有可构造标准答案」的场景（那时门禁只能到 G2/G3/G5，业务成绩必须标 NOT_SCORABLE）。
- **不得**用模拟模型层冒充真实模型层；**不得**为了让门禁变绿而删测试/缩分母/改 Gold/改阈值。

**验证案例（本轮）**：
- 本轮考试台 `tools/dd_v1_exam_suite.py` ＋ `backend/tests/fixtures/dd-v1-exam-suite/` ＋
  `backend/tests/test_dd_v1_exam_suite_l1.py|l2.py|test_dd_v1_model_participation_l3.py` ＋
  `backend/config/dd_v1_delivery_gate.v1.json`。
- 本轮实证：考试台在**合成考场**上抓出 4 个 CI 全绿时不可见的活缺陷（D1/D2/D3/D4）。

## 4. 对 SCP / GCCSEG 的修改建议（**草案**，未擅自发布）

| 编号 | 建议 | 落点 | 理由（本轮实证） |
|---|---|---|---|
| S1 | **端到端测试必须走生产入口** | 测试规范 | 平行入口 ⇒ 真实事故不可见 |
| S2 | **夹具/标准答案的标识必须与被测系统同源** | 测试规范 | 自造 ID ⇒ ID 类缺陷结构性免疫 |
| S3 | **夹具必须先验非退化** | 测试规范 | 退化夹具 ⇒ 满分假象 |
| S4 | **断言必须 fail-closed** | 测试规范 | 找不到输入报 PASS ⇒ 假绿 |
| S5 | **阈值/门槛必须考试前冻结并进版本控制** | 交付门禁规范 | 事后改阈值 ⇒ 门禁失效 |
| S6 | **「模型参与」必须到进程级证据** | AI 接线规范 | 适配器存在 ≠ 模型参与 |
| S7 | **真实模型调用必须有失败路径回归** | AI 接线规范 | 超时/非零退出/凭证缺失/垃圾输出 |
| S8 | **交付前必须产出「可复跑证据包」**（运行清单含 SHA/环境/模型/数据版本/成绩/失败项） | 交付规范 | 复核者要能**复跑**，不能只读报告 |
| S9 | **环境口径（代理/缺依赖/排除项）必须写进机读报告** | 交付规范 | 不隐藏失败，也不让环境漂移改结论 |

**独立复核通过并经波总批准后**才合并为全局正式规范。
