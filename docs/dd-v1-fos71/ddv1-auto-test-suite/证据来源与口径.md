## 0 自我维护声明（★ 别按本文件里的 sha 导航）

★ 本文件出现的任何 commit sha **只表示「该产物引入于哪一笔」**，
**不表示当前 head**，**不要按它导航**。
⇒ 接手时一律**现读**：远端分支 tip 用 `git ls-remote --heads`，
本地用 `git rev-parse HEAD`；**冻结锚点用 git tag**（`ddv1-auto-exam-v1`），
读法必须是 `git rev-parse ddv1-auto-exam-v1^{commit}`（**带 `^{commit}`**）。

## 3 ★ 为什么会出现「证据锚点 ≠ 当前 head」

上一任施工者的做法是：**在目标 commit 的干净树上重生成证据，再把证据单独提交**。
所以「证据锚点」与「分支 tip」天然**差一笔**（证据提交本身又前进了一格）。
⇒ 这是**已知的、可解释的**形态，**不是**「证据与代码不对应」。

★ **判据**（什么时候才算真出问题）：
1. 证据所锚的 commit 与**产出该读数的代码**必须一致（运行清单里的 `git_sha` 就是干这件事）；
2. 证据**所锚的代码路径**在当前 head 上**没有变**（变了就要重跑）；
3. 门禁报告里 `handoff_sha256_selfcheck` 必须与**当前**交接包逐位一致
   —— ★ 这条**曾经没人校验**，现已由
   `backend/tests/test_dd_v1_delivery_doc_consistency.py` 变成机器可判的红。

## 4 云端接管的诚实边界

- **云端没有真实模型凭证**（环境里只有 `GITHUB_TOKEN`）⇒
  **三名真实考生的考试无法在云端重跑**；云端只能重跑**规则基线**与 **pytest**。
- ⇒ 凡涉及**真实模型读数**（G3 真实模型、G8 真实模型参与）的产物，
  其锚点仍是上一任施工者机器上的那次运行，**本文件如实标注，不假装在云端重生成过**。
- ⇒ **若某次改动触及考试/评分/门禁代码本身**，则必须回到有凭证的环境重跑，
  或**明确记为未重生成**，**不得**拿旧读数冒充新读数。

## 5 下一任施工者的规矩

1. **改了考试/评分/门禁代码** ⇒ 在**干净树**上重跑对应考试 ＋ pytest ＋ 门禁，重新锚定；
2. **只改了文档/工具** ⇒ 至少重跑 pytest（用例数会变）与门禁（`git_sha` 与交接包自证会变），
   并**如实**说明真实模型那部分是否重生成；
3. **改了交接包里的任何文件** ⇒ 必须重算 `handoff/SHA256SUMS`（它**不含自身**，无自指循环），
   否则 `shasum -a 256 -c SHA256SUMS` 会出 FAILED；
4. ★ **不得**把「读不到远端」写成「远端没有」；**不得**把「未重生成」写成「已通过」。
