> 沿用本仓既有做法（见 `docs/dd-v1-fos71/ddv1-exam-v1/版本锚点.md`），
> **要点：文档里不写死自己的 SHA** ⇒ **没有自指循环** ⇒ 任何时候都能核。

## 1. 三个锚点

| 锚点 | 在哪 | 怎么读 |
|---|---|---|
| **不可变冻结锚点** | 远端 git tag（**annotated**） | `git rev-parse ddv1-auto-exam-v1^{commit}` ⇒ 40 位 **commit** SHA |
| **本目录内容的版本** | 仓内 | `git log -1 --format=%H -- docs/dd-v1-fos71/ddv1-auto-test-suite/handoff/` ⇒ 即**本文件所在提交** |
| **基线** | 仓内 | `bf68cf94c2744624445b6ea992e41fc3f0b1b78e`（＝ PR#86 的 head；PR#86 本身**未合并**） |

> ★★ **必须带 `^{commit}`**：本 tag 是 **annotated tag**，
>   `git rev-parse ddv1-auto-exam-v1` 返回的是 **tag 对象**的 SHA（`d9f7455…`），
>   **不是**它指向的 commit ⇒ 与「目录内容版本」对不上。
>   `git rev-parse ddv1-auto-exam-v1^{commit}` 才返回 commit SHA。
>   （Windows PowerShell 里 `^{commit}` 需加引号：`git rev-parse "ddv1-auto-exam-v1^{commit}"`。）

### ★ 为什么用 tag 而不是把 SHA 写进文档

文档里写死自己的 SHA ⇒ 改一次文档就要改一次 SHA ⇒ **自指** ⇒ 必然对不上。
历史提交里已经踩过这个坑（见 `0103f3f`：「交接指南的冻结锚点改成**不可变 tag**」）。
⇒ **tag 是唯一稳定的锚点**；目录版本用 `git log -- <dir>` 自解引用。

## 2. 自核（一条命令）

```bash
# 仓内：核本目录文件没被改过
cd docs/dd-v1-fos71/ddv1-auto-test-suite/handoff && shasum -a 256 -c SHA256SUMS

# Windows PowerShell：
cd docs\dd-v1-fos71\ddv1-auto-test-suite\handoff
Get-Content SHA256SUMS | ForEach-Object { $p,$h = $_ -split '  ',2; if ((Get-FileHash $p -Algorithm SHA256).Hash -ne $h) { "FAILED $p" } }
```

★ `SHA256SUMS` **不含自身**（无自指循环）⇒ 改了任何文件都要重算，否则自核会出 1 条 FAILED。
