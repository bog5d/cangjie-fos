## 1. 复跑顺序（**从上到下**执行）

### 第 0 步 · 环境自检

```powershell
cd <仓根>
cd backend
python -m venv .venv
.\.venv\Scripts\pip install -e ".[dev]"
cd ..
```

### 第 1 步 · 确认版本（**不一致就停**）

```powershell
git rev-parse HEAD
```

把输出与 `README.md` §「冻结 SHA」**逐位比对**。不一致 ⇒ **停止并报告**，不要继续。

### 第 2 步 · L1 程序层测试（不依赖模型）

```powershell
cd backend
.\.venv\Scripts\python -m pytest -q tests/ --ignore=tests/test_doctor_script.py
cd ..
```

**怎么判断成功**：末尾出现 `passed` 且**没有 `failed`**；`skipped` 允许（真实模型那层默认 opt-in 跳过）。

> ★ **为什么排除 `tests/test_doctor_script.py`**：
> 它要求仓内有 `.env` 与 `frontend/node_modules`，本机/沙箱都没有 ⇒ **生产 CI 同样排除**
> （见 `.github/workflows/ci.yml`）⇒ 口径与 CI 一致，**不是**为了让成绩好看。

### 第 3 步 · L2 模拟模型端到端 + L3 参与证明

```powershell
cd backend
.\.venv\Scripts\python -m pytest -q tests/test_dd_v1_exam_suite_l1.py tests/test_dd_v1_exam_suite_l2.py tests/test_dd_v1_model_participation_l3.py
cd ..
```

**怎么判断成功**：`31 passed, 1 skipped`（skip 是真实模型那层，需 opt-in 才有）。

### 第 4 步 · 三场自动考试（**产成绩单**）

```powershell
$env:DDV1_EXAM_PLANE = "$env:USERPROFILE\.cangjie-ddv1-exams"   # 隔离数据面，默认在仓库之外
.\backend\.venv\Scripts\python tools\dd_v1_exam_suite.py run --exam A
.\backend\.venv\Scripts\python tools\dd_v1_exam_suite.py run --exam B
.\backend\.venv\Scripts\python tools\dd_v1_exam_suite.py run --exam C
```

**怎么判断成功**：每场打印一行成绩摘要；`rc=0`。
运行清单落在 `$env:DDV1_EXAM_PLANE\<exam>\runs\<run_id>\运行清单.json`。

> ★ **数据面隔离**：默认 `~/.cangjie-ddv1-exams`（macOS/Linux）或 `%USERPROFILE%\.cangjie-ddv1-exams`（Windows），
> **在仓库之外** ⇒ 合成材料**永远不污染真实业务库**。

### 第 5 步 · 门禁判定（G1—G7）

```powershell
# G1：把 pytest 结果转成门禁可读的机读报告
.\backend\.venv\Scripts\python tools\dd_v1_exam_suite.py pytest-report --out .audit\gate-runs\g1_pytest.json

# 把三场考试的运行清单汇入门禁目录
#   （Windows PowerShell：逐场复制）
```

**怎么判断成功**：`g1_pytest.json` 里 `counting_ok=true` 且 `failed=0`。
> ★★ `counting_ok=false` ⇒ **FAIL**，不是「0 条通过」。这是刻意设计的 fail-closed：
> 计数拿不到时**必须红**，不能静默算成通过。

### 第 6 步 · 覆盖率报告

```powershell
.\backend\.venv\Scripts\python tools\dd_v1_exam_suite.py coverage --runs .audit\gate-runs --out .audit\gate-runs\覆盖率报告.json
```

**怎么判断成功**：报告里 `自动化覆盖率 ≥ 0.90`（本轮实测 **50/51 = 98.04%**，
且与同包 `README.md` §1、`COVERAGE.md` §2 **同源同数**），
且**覆盖率与通过率分列**。
> ★ 若你算出来的数与上面不一致，**以你机器上的机读报告为准**，并把差异回给我
> （分母来自 `backend/config/dd_v1_acceptance_items.v1.json` 的 54 项清单，**不得**自行缩分母）。

## 2. 一键复跑（**给 Reviewer 的最短路径**）

```bash
# macOS / Linux
DDV1_EXAM_PLANE=~/.cangjie-ddv1-exams \
  backend/.venv/bin/python tools/dd_v1_exam_suite.py run --exam A && \
DDV1_EXAM_PLANE=~/.cangjie-ddv1-exams \
  backend/.venv/bin/python tools/dd_v1_exam_suite.py run --exam B && \
DDV1_EXAM_PLANE=~/.cangjie-ddv1-exams \
  backend/.venv/bin/python tools/dd_v1_exam_suite.py run --exam C
```

```powershell
# Windows PowerShell
$env:DDV1_EXAM_PLANE = "$env:USERPROFILE\.cangjie-ddv1-exams"
.\backend\.venv\Scripts\python tools\dd_v1_exam_suite.py run --exam A
.\backend\.venv\Scripts\python tools\dd_v1_exam_suite.py run --exam B
.\backend\.venv\Scripts\python tools\dd_v1_exam_suite.py run --exam C
```

> ★ 三场考试互相独立，**可以并行跑**（各自独立数据面）——但同一台机器上并行会互相抢磁盘 IO，
> 建议**串行**，实测串行更稳。

## 3. 失败时怎么办

| 现象 | 含义 | 该做什么 |
|---|---|---|
| `counting_ok=false` | 机读报告计数失败（**不是**「零失败」） | 看 `g1_pytest.json` 的 `counting_parse_error`；**不要**改测试让它变绿 |
| `status=NOT_SCORABLE` | 标准答案未提供/未映射/未人工确认/检测到泄漏 | **这是正确行为**，按 `README.md` 的 BLOCKED 清单找对应责任人，**不要**改成 SCORED |
| `safety_gate=FAIL` | 安全闸命中（错主体/错年度/受限误交/未经批准/哈希不符） | **真实问题**，不许调分；总分封顶 59 是规范定的 |
| `total_score=0` 且有有效标准答案 | 0 件交付 ⇒ **如实 0 分** | **这是正确行为**（#85 永久红线），不要改写成 `NOT_SCORABLE` |
| `model.participated=false` | 模型没真参与（走了规则兜底） | 真实模型层**不得**用规则兜底冒充 ⇒ 查凭证/网络/超时 |

| 证据 | 路径 |
|---|---|

| 成绩单 | `<数据面>/<exam>/runs/<run_id>/grade/成绩单-*.json` |
| 真实模型留证 | `.audit/real-model/{stderr.log,real-model-evidence.json}` |
| 独立复核报告 | `.audit/gate-runs/g6_reviewer.json` |

> ★ 三场考试的**完整数据面**在仓库之外（`DDV1_EXAM_PLANE`）⇒ **不提交进 Git**。
> 进 Git 的是**运行清单 + 报告**（机读、可复跑、无客户材料）。
