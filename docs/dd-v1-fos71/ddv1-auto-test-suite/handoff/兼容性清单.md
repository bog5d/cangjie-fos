## A. 代码层面 · **Mac 已验、路径与编码写法是跨平台的**

| # | 项 | 状态 | 说明 |
|---|---|---|---|
| A1 | **文件路径拼接** | ✅ 跨平台写法 | 考试台与三层测试**全部用 `pathlib`**（`d / "data"`、`out / "运行清单.json"`）⇒ Windows 的 `\` 无需特殊处理 |
| A2 | **绝对路径注入 `sys.path`** | ✅ 跨平台写法 | `sys.path.insert(0, str(BACKEND / "src"))` 用绝对路径 ⇒ Windows 可用 |
| A3 | **文件读写编码** | ✅ 跨平台写法 | 全部显式 `encoding="utf-8"` ⇒ 不受 Windows 默认 GBK 影响 |
| A4 | **中文文件名** | ⚠️ | 产物名含中文（`运行清单.json`、`成绩单-*.json`）⇒ NTFS 本身是 UTF-16，**文件名没问题**；但**命令行回显**见 B1 |
| A5 | **调用生产入口的方式** | ✅ | 考试台是 `import dd_team_channel` **进程内调用**（不是 subprocess）⇒ **没有 Windows 进程创建差异**（无黑窗弹窗问题） |
| A6 | **解释器路径** | ⚠️ | `cmd_pytest_report` 找 `backend/.venv/bin/python`（POSIX 布局）⇒ Windows 上不存在 ⇒ **自动回落到当前解释器**。逻辑正确，但 Windows 上跑的是 `sys.executable`，需确认它是目标 venv 的解释器 |
| A7 | **Python 版本下限** | ⚠️ | 代码用到 `dataclass(slots=True)`（**3.10+**）与 `X \| None` 类型语法（**3.10+**）⇒ Windows 上若仍用 3.9 会**语法错**，不是运行错 |
| A8 | **`git` 命令调用** | ⚠️ | `git rev-parse HEAD` / `git status --porcelain` 用于记录 SHA 与脏状态 ⇒ Windows 需 `git` 在 PATH；**未装 git ⇒ SHA 记为 `UNKNOWN`**（不崩，但证据变弱） |
| A9 | **★ 考场数据面排他锁（本轮新增）** | ✅ **跨平台写法** | `tools/dd_v1_exam_suite.py` 的考场锁**不用 POSIX 专属的 `fcntl` 硬依赖**：能 `fcntl` 就用 `flock`，否则用 Windows 原生 `msvcrt.locking`（**按字节区间**锁第 0 字节），两边都没有才**如实降级**并在运行清单的 `environment.plane_lock_backend` 里报出来（**不假装有保护**）。★ 锁**随进程退出自动释放** ⇒ 强杀残留进程不留残锁 |

## B. Windows 特有风险 · **❌ 未在 Windows 上验过（必须刘江验）**

| # | 项 | 为什么会出事 | 怎么验 | 预期 |
|---|---|---|---|---|
| **B1** | **控制台中文输出编码** | Windows 控制台默认代码页可能是 **GBK(cp936)**；Python 在 Windows 的 stdout 编码跟随 locale ⇒ 打印中文（义务文本、题号、中文文件名）可能 `UnicodeEncodeError`，或输出乱码 | 直接跑 `run --exam A`，看终端有没有报错/乱码 | 不报错即可 |
| **B2** | **命令行传中文路径** | `--checklist "资料\清单.tsv"` 这类中文参数在 cp936 控制台可能被转码破坏 | 用**含中文名**的目录跑一次 | 参数能被正确识别 |
| **B3** | **依赖安装方式** | Mac 用 `uv sync --extra dev`；Windows 上 `uv` 未必装 ⇒ 需 `pip install -e ".[dev]"`。**某些 dev 依赖在 Windows 上装不上** | 照 `复跑命令.md` §1 第 0 步装 | 装得上且能 import |
| **B4** | **文件锁 / 杀毒软件** | Windows Defender 实时扫描会锁新建文件 ⇒ 并行跑三场考试可能「Permission denied」 | 串行跑 A→B→C | 三场都 rc=0 |
| **B4'** | **★ 考场数据面锁（Windows 分支）** | 本轮新增的排他锁在 Windows 上走 `msvcrt.locking`（**按字节区间**）⇒ 语义与 POSIX `flock` **不完全等价**（前者不能跨 `open()` 模式混用）⇒ 若锁判成「已被占」，Windows 上会报 `EXAM_PLANE_BUSY:<考场>`（**人话**，可等它跑完再跑） | 串行跑 A→B→C（**别并行**）；若报 BUSY，确认没有残留 python 进程再重试 | 三场都 rc=0，且运行清单 `environment.plane_lock_backend`＝`msvcrt` |
| **B5** | **路径长度** | Windows `MAX_PATH` 260 限制；材料目录层级深时可能爆 | 跑 `run --exam C`（41 份材料、嵌套目录） | 不报路径过长 |
| **B6** | **行尾 CRLF** | 清单是 `.tsv`；若被 Git 转成 CRLF，解析可能带上 `\r` ⇒ 题号/字段尾部多字符 | 跑之前 `git config core.autocrlf` 看一眼；跑完核对题数 | 仍是 3/9/42 题 |
| **B7** | **`os.fsync` / 文件系统语义** | SQLite/落盘在不同文件系统上的刷写时机不同 ⇒ 可能出现「清单已写、DB 未刷」的时序差异 | 连跑两次同一场考试 | 两次读数一致 |
| **B8** | **真实模型进程** | 本机 `dsh` 的启动方式、凭证文件路径、换行符在 Windows 上不同 | 见 `BLOCKED-清单.md` BLOCKED-1 解锁后再验 | 参与证明为真 |
