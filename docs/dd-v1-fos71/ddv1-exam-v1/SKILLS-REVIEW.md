## 三、新增候选（1 项，**未发布**）

### 候选卡：`dd-v1-exam-and-grading`

- **类级定位**：任何「模型产出 vs 人工权威答案」的比对型工程（不只是尽调）。
- **要解决的通用形态**（本轮亲历，可迁移）：
  1. **「未接入」被写成「不存在」** —— 标准答案/权威答案有**四态**（未提供 / 未映射 / 未人工确认 / 冲突），
     必须**分开报**，否则会把「工程没接上」误报成「业务本来就没有基准」。
  2. **开考前的 Gate** —— 把「必然失败的原因」（如多主体库 + 义务未指名主体 ⇒ 全盘 UNCERTAIN）
     在**跑之前**顶出来，而不是跑完才发现。
  3. **0 分 ≠ 不可评分** —— 有效基准 + 0 产出 ⇒ 报 0 分；只有基准客观不可得才 NOT_SCORABLE。
  4. **零命中零分** —— 「理解率高但一件没选对」在业务上就是 0 分，不得被理解率洗成部分成功。
  5. **内容寻址优于文件名** —— 人工包与系统库文件名/路径不同但内容相同时，必须按 SHA256 对上。
  6. **安全闸独立计分** —— 错主体/错年度/受限外发/哈希不一致单列并封顶，不得用业务分抵消。
- **可迁移产物**：`dd_v1_gold_service.py`（Gold 清单 + 内容寻址解析）、`dd_v1_exam_service.py`
  （机器答卷 + 隔离阅卷 + 冻结口径 + 版本对比）、`dd_v1_exam_preflight_service.py`（开考前 Gate）。
- **晋级路径**：需①第二方独立复核；②脱离 FOS 语境做一次**跨项目**演练；③Owner 批准后才可发布。
- **本轮状态**：**候选**，未验证、未发布。

## 四、复盘发现的**本项目**可复用经验（已写进代码注释，不另立技能）

1. **「未接入」与「不存在」必须用不同枚举值** —— 已落 `GOLD_STATES` 五态 + 预检逐项输出。
2. **停止条件不能只靠「结论稳定」** —— 巧合式停止会漏掉排在窗口外的正确答案；
   必须「**结论稳定 且 候选池已穷尽**」才算停（`dd_v1_candidate_expansion_service`）。
3. **「理解」与「作答」是两个指标** —— 看懂但找不到材料（弃答）时，理解率 1.0、作答率低、**总分仍是 0**。
4. **模型提案必须与它自己选的文件自洽** —— 「说要审计报告却挑了执照」要能被机器拒掉，
   否则「AI 真的做了语义判断」与「AI 只是跑规则脚本」无法区分。
5. **实体识别不能只看目录** —— 分类目录不是法人级；识别要按证据强度分级，且**认不出就保留不确定**。
6. **`__pycache__` 陈旧会伪造出「代码没生效」** —— 本轮两次被它误导（同一轮里
   「改了却没生效」与「真失败」长得一模一样）；**跑测试前必须清 `__pycache__`**。

### 5.2 本轮**新学到的**两条纪律（已写进代码注释/本文）

7. **「写好了 + 有单测」≠「生效了」** —— 三个模块上一版全部有完整实现、全部有单测，
   但**生产链路零调用方** ⇒ 真实组包里一次都没走。
   ⇒ **判据必须是「生产链路上有没有调用方」**（`grep` 调用方为 0 ⇒ 纸面承诺），
   而不是「模块有没有被测过」。⇒ **接线后必须能在机读产物里看到调用留下的读数**
   （本轮：`candidate_expansion` 出现在机读 JSON 顶层 ⇒ 证明真的跑了）。
8. **接线类改动必须跑全量，不能只跑自己新写的测试** —— 本轮接线改的全是**既有链路**
   （bridge / 答卷 / 阅卷）⇒ 只跑新写的 36 条会**漏掉崩溃**；
   实际是**既有**测试 `test_dd_v1_bridge.py::test_bridge_on_empty_library_does_not_raise`
   在全量里当场抓出 `agent_receipt` 未绑定（`UnboundLocalError`）。
   ⇒ 推论：**「既有测试挂了」不一定是「环境问题」** —— 本轮多出来的那一条失败，
   恰恰是**本轮自己引入的** ⇒ 失败集合要**逐条比对**，多一条就是新缺陷。

## 第 5 轮复核（CONDITIONAL）的复盘（2026-10-29）

★ 第 5 轮复核抓到 3 条重要缺陷 ＋ 1 条条件项 ＋ 1 条文档计数错误。**四条教训**（跨项目通用）：

**纪律 9：「按自填字段判身份」＝ 没有身份。**
  `adapter_provenance(adapter_id)` 是**字符串查表** ⇒ `class _SpoofAdapter: adapter_id="codex-cli"` 即得 `HARNESS_MODEL`。
  ⇒ **凡是「凭据」类判定，判定输入必须是**不可自填的东西**（这里改成**适配器实现类**的精确类型匹配）。
  ⇒ **判据**：`grep -rn "adapter_id\|provider\|model_id" <判定函数>` ⇒ 若判定入参是**字符串**，就是可伪造的。

**纪律 10：新增 kwarg 会打断既有「替身/桩函数」的入参形状。**
  我第一版修「透传 `confirmed_map`」时**无条件**多传了一个 kwarg ⇒ `test_dd_v1_candidate_expansion.py` 的 **9 条**桩测试
  （`def _match(library_id, obligation_id, candidate_cap=20, db_path=None)`）全红。
  ⇒ 修法：**只在确实有该值时才多传**（`if confirmed_map:` 分支）⇒ 既有调用形状一字不变。
  ⇒ **判据**：改完接线**必须跑既有测试文件**（不是只跑自己新写的）——「只跑新写的会漏掉崩溃」这条纪律的**第二次**兑现。

**纪律 11：文档写「机制是什么」之前，先跑一遍机制。**
  `PREBAKED_RESULT` 在文档里写了一整轮，实际**全仓没有任何代码产出它**（映射表漏了一项）⇒ 刘江照文档读会拿到错的读数。
  ⇒ **判据**：文档里每个**枚举值/档位**，都要在源码里找到**至少一个产出点**（`grep -rn "PREBAKED_RESULT" src/` ⇒ 要有赋值处，不是只有接受集合）。

**纪律 12：「分数没变」的归因要**逐句对实现**，不能靠推演。**
  我写「答卷来自夹具预置的 `replies/`、不从检索结果生成」⇒ **与实现不符**（脚本根本没读 `replies/`）。
  ★ 更要紧的是：我据此写了「本轮只改覆盖率、没改判定」⇒ **也不准确**（a4/cap=2 实测库级判定分布从 `RESTRICTED×8` 变成 `CONFLICT×6+RESTRICTED×2`）。
  ⇒ **判据**：凡是「因为 X 所以 Y 不变」的归因，**必须先确认 X 真的成立**（读代码，不是读自己的记忆）；⇒ 且**归因要同时说清「什么变了、什么没变」**。
  ⇒ **这次是 Reviewer 抓出来的**（我自己的读数只到「分数没变」）⇒ ★ **独立复核的价值就在这里**。

**纪律 13：「修好一个入口」≠「这个不变量守住了」。**
  第 5 轮我把「参与身份只认实现」修在了**桥接层**；第 6 轮复核在**答卷层**抓到同一个洞：
  `adapter.provenance` 是**适配器自己写的自由字段** ⇒ 答卷直接采信它 ⇒ 自填即可冒充。
  ⇒ **判据**：凡声明过的不变体（如「参与身份不可自填」），**逐个枚举能产生该副作用的全部入口**
  （桥接层／答卷层／CLI／run_record 落盘层），把守卫接到**每一个**上。
  ⇒ **落点**：让**权威值带盖章**（`provenance_source`），下游**只认盖章** ⇒ 一处盖章、处处可验。

**纪律 14：把「归一」做成**单一索引**＝制造串味。**
  `_confirmed_index` 把归一后的写法也塞进精确档 ⇒ 表里 `FILE-ABC` 的归一形 `file-abc`
  占掉了真正那条 `file-abc` ⇒ **人工确认反了**（材料被判成另一个主体）。
  ⇒ **判据**：查表要**两级**（原样键精确档 ＋ 归一档兜底），**归一后的写法不许进精确档**。
  ⇒ **通用**：任何「查表键归一」的改动，都要问一句「**两个不同的键会不会归一到同一个**？会 ⇒ 串味」。

**纪律 15：幂等护栏挡不住「范围算错」。**
  `rest_push.py <base>..<tip>` 的幂等护栏能挡「同一条重跑」（它比的是远端 tip 与目标 sha），
  但**挡不住**我把 base 写成「上一条**本地**提交」—— 本地那条在远端是**另一个 sha**（REST 重建）⇒
  范围里**多出**一条已推过的提交 ⇒ 又建了一条**内容相同、sha 不同**的孪生提交。
  ⇒ **判据**：推之前，`base` 必须取**远端现读**的那条（REST 重建后的 sha），且范围里**不含**已推过的内容。
  ⇒ 推完**逐路径核**（`git/trees` + `contents`）⇒ 顺带就能发现「两条 tree 相同」。
