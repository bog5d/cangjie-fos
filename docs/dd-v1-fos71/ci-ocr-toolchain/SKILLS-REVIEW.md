## 2. 本轮踩到并已登记的坑（**候选技能**）

### 候选 A：《CI 红灯的「环境缺失」形态》

- **症状**：check-run `FAILURE`、有真实耗时、step 1–N 全 success，只有跑测试那步红。
- **根因**：测试依赖**系统级二进制与字体**（`shutil.which('tesseract')` + 绝对路径字体清单），
  而 CI workflow 只装 pip 依赖 ⇒ runner 上根本没有。
- **判据**：
  1. 失败 ID 全集**收敛到单个文件**（本例 10/10 落在 `test_dd_v1_ocr.py`）⇒ 指向共同前置条件；
  2. 报错字面是**环境断言**（「本机缺少 X」「本机没有可用的 Y」）而不是**行为断言** ⇒ 指向环境；
  3. **同一份代码在别的机器上全绿** ⇒ 差异在环境；
  4. 修法必须是**补环境**，不是 skip/xfail/弱化断言。
- **反向形态**：如果失败 ID 散落在多个文件、报错是行为断言 ⇒ **不是**环境缺失，别往这个方向修。

### 候选 B：《移动标签上的 CI 修复要跨发行版验包名与落点路径》

- **症状**：workflow 用 `runs-on: ubuntu-latest`（**移动靶**），修完当前镜像的缺包，
  镜像一迁移就又缺。
- **根因**：`ubuntu-latest` 正在 24.04 → 26.04 迁移（官方公告 2026-10-19 起 rollout）。
- **判据**：
  1. **包名要跨发行版核对**（查 `dists/{codename}/{main,universe}/binary-amd64/Packages.gz`，
     不要只看当前发行版）；
  2. **包可能换仓库**（本例：tesseract 系列在 `universe`，`fonts-noto-cjk` 在 `main`）⇒ 只配一个源会装不上；
  3. **落点路径要按 `.deb` 文件清单核对**（`dpkg-deb -c`），不能凭包名推断 ——
     测��的 `FONT_CANDIDATES` 是**绝对路径**，路径差一个字符就等于没装；
  4. 修法要**在装完的当下自证**（`command -v` / `--list-langs` / 文件存在），
     让环境问题**在自己的步骤**红，而不是让下游业务用例以误导性信息红。
- **真实根因 ✓ / 回归复验 ✓** ⇒ 列入候选，**未经批准不得合入**技能库，本轮**未写入**。

### 候选 C：《包索引查询要直接打源站，不要依赖聚合站》

- **症状**：`packages.ubuntu.com` 在本沙箱不可达（http=000 / 500），
  Launchpad 的 `getFiles` API 路径猜错返回 404。
- **有效解**：`archive.ubuntu.com/ubuntu/dists/<codename>/{main,universe}/binary-amd64/Packages.gz`
  （源站，实测 200）→ 本地解包解析 → 再按 `Filename` 字段取 `.deb` → `dpkg-deb -c` 看**真实落点**。
- **判据**：查包名/查落点**直接打源站**；聚合站不可达时不是「查不到」而是「通道不通」。
